# TTV v0.6 — бой и игровые действия

Версия 0.6 превращает прежнюю простую очередь ходов в универсальный боевой runtime. Он не привязан к D&D: мастер управляет инициативой, здоровьем, эффектами и состояниями, а конкретный лист персонажа по-прежнему задаётся схемой игровой системы.

## Пользовательский сценарий

1. Мастер размещает видимые фишки на активной сцене.
2. В разделе `Сессия` выбирает автоматическую или ручную инициативу.
3. Начинает бой и получает отсортированную очередь первого раунда.
4. Во время боя мастер может изменить инициативу, передать ход любому участнику, нанести урон, восстановить здоровье, добавить или снять эффект.
5. `Следующий ход` переводит очередь дальше и создаёт новый раунд после последнего участника.
6. В автоматическом режиме эффекты с длительностью уменьшаются на границе раунда и исчезают после последнего раунда. В ручном режиме мастер полностью управляет ими сам.
7. Игроки видят актуальную очередь, инициативу и активные эффекты через разрешённое состояние кампании.

## Инициатива

- Автоматический режим бросает `d20` на сервере для каждого видимого участника активной сцены.
- Если у персонажа есть числовое поле `initiative` или `initiative.value`, оно добавляется как модификатор.
- Ручной режим принимает значения мастера; участник без введённого значения получает `0`.
- Одинаковые значения стабильно разрешаются по типу фишки и имени.
- Мастер может отредактировать инициативу во время боя; очередь пересортируется.

## Урон и лечение

Боевые действия используют существующую совместимость универсальных листов со здоровьем. Сервер ограничивает итог диапазоном от `0` до максимума ресурса и разрешает действие только GM-ролям для участника активного боя.

## Эффекты и состояния

Каждая запись хранит:

- персонажа;
- название;
- тип: `Состояние` или `Эффект`;
- необязательную длительность в раундах.

Эти данные находятся в `campaign_runtime`, синхронизируются существующим realtime-сигналом и очищаются при завершении боя.

## База данных

Миграция: `supabase/migrations/0029_v06_combat_actions.sql`.

Она добавляет в `campaign_runtime`:

- `combat_initiative jsonb`;
- `combat_effects jsonb`;
- `combat_control text` (`automatic` / `manual`).

Новые RPC закрыты от `anon`, проверяют GM-доступ и валидируют кампанию, участника, диапазоны и пользовательский текст. Старый `start_campaign_combat(uuid)` сохранён как совместимая обёртка автоматического запуска.

## Проверка

```bash
npm test
npm run typecheck
npm run build
supabase test db
```

Ручная smoke-проверка:

1. Начать автоматический бой и убедиться, что инициатива заполнена и очередь отсортирована.
2. Завершить бой, начать ручной и проверить введённые значения.
3. Поменять инициативу участника и передать ему ход кнопкой номера.
4. Применить урон и лечение к выбранному участнику.
5. Добавить состояние на 1 раунд и эффект без срока.
6. В автоматическом режиме пройти до нового раунда: временное состояние должно исчезнуть.
7. В ручном режиме пройти новый раунд: длительность должна остаться прежней.
8. Открыть Player View и проверить очередь, инициативу и эффекты.
9. Завершить бой через встроенное подтверждение и убедиться, что runtime очищен.
