# TTV v0.3 — Realtime multiplayer

v0.3 превращает online campaign из общей базы данных в живую совместную игровую комнату.

## Что входит

- приватный realtime-канал на каждую кампанию;
- Presence: видно, сколько участников сейчас в кампании;
- live movement: движение видимой фишки отправляется другим участникам во время перетаскивания;
- финальная позиция фишки сохраняется в Postgres;
- смена сцены мастером обновляет стол остальных участников без ручной перезагрузки;
- изменение HP обновляет Player/GM View без ручной перезагрузки;
- создание персонажей/NPC и изменения инвентаря инвалидируют состояние всей комнаты;
- быстрая выдача простого предмета выбранному персонажу;
- общий combat runtime: начало боя, раунд, текущий ход, следующий ход и завершение боя;
- права на перемещение фишек и изменение HP проверяются серверными RPC;
- игрок не получает скрытые записи через realtime-сообщения: канал отправляет только минимальный сигнал об изменении, после чего клиент перечитывает разрешённые RLS данные.

## Модель синхронизации

```text
Transient state
  token drag
    -> Realtime Broadcast
    -> другие клиенты сразу двигают фишку

Persistent state
  token drop / HP / scene / inventory / combat
    -> PostgreSQL
    -> state_changed broadcast
    -> клиенты обновляют разрешённое состояние
```

Broadcast/Presence используют приватный topic:

```text
campaign:<campaign_id>
```

Доступ к нему разрешён только участникам соответствующей кампании через политики `realtime.messages`.

## Что сознательно не входит в v0.3

- загрузка пользовательских карт и ассетов;
- полноценный fog editor;
- walls/light;
- сложная инициатива и автоматизация правил;
- dice log;
- события карты/скрипты;
- voice/video.

Эти системы идут после проверки базового multiplayer flow.

## Acceptance test

1. GM создаёт online campaign и сцену.
2. GM создаёт player actor.
3. Второй аккаунт входит по invite link.
4. GM назначает actor игроку.
5. GM и Player открывают один стол в двух браузерах.
6. Оба видят `2 в сети`.
7. Игрок двигает свою фишку — GM видит движение до отпускания мыши.
8. После отпускания и обновления страницы позиция остаётся сохранённой.
9. GM меняет HP — Player View обновляется автоматически.
10. GM выдаёт предмет — он появляется у игрока автоматически.
11. GM переключает сцену — Player View переходит на неё автоматически.
12. GM начинает бой и переключает ход — Player View видит тот же раунд и текущего участника.
