# GM UX — Context First

Экспериментальная линия для ветки `test/gm-ux-context-first`.
Цель: карта остаётся главным объектом, панели появляются по запросу.

## Принципы

1. **Map first** — постоянный chrome минимален.
2. **Одна задача — одна поверхность** — не держать library + inspector + workshop одновременно без нужды.
3. **Режимы стола** — Игра / Бой / Подготовка меняют доступные действия.
4. **Язык RPG** — Герои, NPC, Выдать, Сейчас ходит.
5. **Esc** закрывает верхнюю поверхность.

## Поверхности

| Уровень | Пример | Поведение |
|---------|--------|-----------|
| Context | Карточка выбранного персонажа | Появляется при выборе токена/героя |
| Drawer | Библиотека персонажей | Выезжает с rail, не перекрывает центр карты |
| Workspace | Мастерская, Настройки сцены | Большой overlay, лучше из режима Подготовка |

## Текущий шаг (v1 на этой ветке)

- Библиотека мастера **по умолчанию свёрнута** (только rail).
- Inspector уже схлопывается, когда ничего не выбрано (`gm-inspector-empty` → ширина 0).
- Нижний context bar (`TabletopContextUi`) остаётся точкой входа в режимы и быстрые действия.

## Следующие шаги (не в этом коммите)

1. Floating context card вместо фиксированной колонки inspector.
2. Жёстче разделить Play / Prepare: workshop и scene settings в основном из Подготовки.
3. Убрать dual-path (DOM-bridge в ContextUi → прямые callbacks).
4. Notes как лёгкий drawer, Content только внутри Мастерской.

## Как проверить

1. Открыть онлайн-кампанию в режиме мастера.
2. Карта должна занимать максимум: слева только узкий rail, справа пусто.
3. Клик по иконке «ПЕРСОНАЖИ» на rail — открывается drawer.
4. Клик по токену — появляется inspector справа.
5. Снять выбор (×) — inspector снова схлопывается.
6. H скрывает chrome, Esc закрывает временные панели.
7. `npm test` и `npm run typecheck` зелёные.
